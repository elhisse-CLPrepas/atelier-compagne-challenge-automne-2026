Concepts fondamentaux et erreurs à éviter

Le déclic de la semaine 3
Prompt ponctuel vs. Processus reproductible
La différence qui change tout

  • Entrée définie : Vous spécifiez exactement ce qui est autorisé et interdit
  • Sortie imposée : Format, structure et contraintes clairement définis
  • Contrôles intégrés : Vérifications automatisées à chaque étape
  • Mesure objective : Métriques avant/après quantifiables
  • Documentation systématique : Nommage, versioning et stockage standardisés

  • Modèle stable : Réutilisation du même schéma pour des tâches similaires
  • Limitation des variations : Réduction de la dépendance à l'expertise individuelle
  • Qualité vérifiable : Critères de réussite objectifs et mesurables
  • Diminution des retours : Moins de corrections et d'allers-retours
  • Capitalisation : Accumulation d'optimisations au fil du temps

  • Nommage standardisé : Format ENT-W3-WF-[INTENTION]-[NN]
  • Versioning : Suivi des améliorations (v1, v2, v3)
  • Exemple stocké : Sortie de référence pour validation
  • Indépendance : Un collègue peut exécuter sans votre présence
  • Évolutivité : Base pour l'automatisation complète (RPA, APIs)

🔄 Workflow démonstration : Extraction → Structuration → Tableau
3 prompts distincts - 3 formats imposés - 3 contrôles QA

Rôle : Analyste process qualité
Objectif : Extraire les faits objectifs d'un corpus de demandes sans interprétation ni invention

=== RÈGLES STRICTES ===
1. NE PAS DEVIER : Respecter scrupuleusement le corpus fourni
2. INFO MANQUANTE : Écrire exactement "MANQUANT" si une information est absente
3. PAS DE DONNÉES PERSONNELLES : Remplacer par "[ANONYME]" si présent
4. FORMAT UNIQUE : Sortie exclusivement en JSON valide

=== SCHÉMA JSON OBLIGATOIRE ===
[
  {
    "id_reference": "texte exact de la référence",
    "type_demande": "ticket|note|message|email",
    "demande_principale": "phrase concise de la demande",
    "urgence": "faible|moyenne|haute|MANQUANT",
    "delai_exprime": "texte exact du délai ou MANQUANT",
    "impact_client": "faible|moyen|fort|MANQUANT",
    "informations_manquantes": ["liste", "des", "infos", "manquantes"]
  }
]

=== CORPUS À TRAITER ===
{{COLLER_LE_CORPUS_ICI}}
Contrôle QA : JSON valide (vérifiable avec JSONLint) • Zéro champ inventé • Présence de "MANQUANT" quand applicable 

Rôle : Contrôleur qualité processus
Objectif : Normaliser, enrichir et préparer pour décision

=== RÈGLES DE NORMALISATION ===
1. URGENCE : Harmoniser sur {faible, moyenne, haute}
2. IMPACT : Harmoniser sur {faible, moyen, fort}
3. PRIORITÉ : Calculer automatiquement selon la matrice :
   - Haute urgence + Fort impact = P1
   - Haute urgence + Impact moyen/faible = P2
   - Moyenne urgence + Impact fort/moyen = P2
   - Autres combinaisons = P3
   - Données insuffisantes = "A_REVOIR"
4. ACTION IMMÉDIATE : Proposer une action concrète basée sur les champs présents

=== FORMAT DE SORTIE ===
JSON avec champs ajoutés :
- "priorite_calculee": "P1|P2|P3|A_REVOIR"
- "action_immediate": "texte de l'action proposée"
- "statut_traitement": "en_attente|a_qualifier|a_planifier"

=== DONNÉES D'ENTRÉE ===
{{COLLER_LE_JSON_ETAPE_1}}
Contrôle QA : Règles de priorisation traçables • Cohérence des normalisations • "A_REVOIR" appliqué quand données insuffisantes 

Rôle : Assistant opérationnel de production
Objectif : Générer un tableau de suivi prêt à l'emploi pour l'équipe produit

=== FORMAT IMPOSÉ ===
Tableau Markdown avec colonnes exactes dans cet ordre :

| ID | Type | Demande | Urgence | Impact | Priorité | Action immédiate | Infos manquantes | Assigné à |
|---|---|---|---|---|---|---|---|---|

=== RÈGLES DE PRÉSENTATION ===
1. Une ligne par élément du JSON d'entrée
2. "Infos manquantes" : liste à puces si plusieurs, "Aucune" si vide
3. "Assigné à" : laisser vide ("") pour être rempli manuellement
4. Ne pas ajouter de lignes, de colonnes ou de commentaires supplémentaires

Pratique guidée en binômes

Consignes opérationnelles • Rôles alternés • Livrables concrets
📋 Consignes détaillées
Rôles : Producteur + Contrôleur QA
  1. Choisir un micro-processus : Sélectionnez une tâche répétitive qui prend 15-30 minutes manuellement
  2. Cartographier en 4 lignes : Appliquez le modèle Entrée-Transformation-Sortie-Validation
  3. Découper en 3 étapes max : Chaque étape doit avoir un objectif clair et un format imposé
  4. Définir les contrôles : 1 contrôle vérifiable par étape (ex: JSON valide, colonnes exactes)
  5. Produire une sortie : Générer un exemple fictif de sortie finale
  6. Mesurer l'impact : Noter le temps avant/après et les erreurs typiques

=== GRILLE D'ÉVALUATION (0-2 points par critère) ===
1. REPRODUCTIBILITÉ (0-2) :
   • 0 : Impossible à reproduire
   • 1 : Reproduisible avec difficulté (>30 min)
   • 2 : Reproduisible facilement (≤15 min)

2. CONTRÔLES VÉRIFIABLES (0-2) :
   • 0 : Aucun contrôle explicite
   • 1 : Contrôles partiels ou ambigus
   • 2 : Contrôles complets et testables

3. FORMAT IMPOSÉ (0-2) :
   • 0 : Format libre ou non spécifié
   • 1 : Format partiellement défini
   • 2 : Format strict et imposé

4. ZÉRO INVENTION (0-2) :
   • 0 : Beaucoup d'inventions ou hallucinations
   • 1 : Quelques inventions mineures
   • 2 : Strict respect des données sources

5. DOCUMENTATION (0-2) :
   • 0 : Documentation absente
   • 1 : Documentation partielle
   • 2 : Documentation complète et organisée

Reprise contrôlée sans altération du fond

            

            

              
Rôle : Expert en amélioration qualité
Objectif : Reprendre une sortie de qualité insuffisante en conservant strictement le sens original

=== PRINCIPE FONDAMENTAL ===
NE PAS CHANGER LE FOND, uniquement la forme, la structure et la complétude.

=== RÈGLES STRICTES ===
1. CONSERVER LE SENS : Ne pas altérer le message, les données ou les conclusions
2. CORRIGER LA FORME : Structure, clarté, mise en forme, organisation
3. COMPLÉTER LES MANQUES : Ajouter "MANQUANT" explicitement là où une information est absente
4. RESPECTER LE FORMAT : Sortie finale strictement conforme aux exigences

1. Analyser la sortie actuelle
2. Identifier les problèmes de forme et structure
3. Réorganiser en respectant le format imposé

5. Vérifier la cohérence globale

🛡️ Principe de vigilance qualité

        
Tout workflow qui impacte une décision externe (client, partenaire, régulateur) doit inclure une validation humaine explicite avant mise en œuvre. L'IA assiste et accélère, mais la responsabilité décisionnelle reste humaine.

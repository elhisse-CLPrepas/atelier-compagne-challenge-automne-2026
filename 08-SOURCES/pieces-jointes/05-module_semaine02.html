⚙️ Méthode : le prompt en 6 blocs

Structure obligatoire pour chaque prompt
1. Rôle
Qui parle. Quel périmètre métier.
2. Objectif
Résultat attendu. Mesurable et concret.
3. Contexte
Situation, public, enjeu, contraintes.
4. Données
Autorisées vs interdites. Sensibilité.
5. Contraintes
Règles, ton, longueur, sources imposées.
6. Format de sortie
Structure imposée (tableau, puces, etc.).
📌 Règle absolue : si une info manque → écrire [À COMPLÉTER]
🛡️ Méthodes de contrôle qualité
Reformulation
L’IA reformule la demande, liste les trous et demande des compléments.
Checklists
Validation systématique des 6 blocs, données autorisées/interdites, format.
Références internes
Usage obligatoire des DOC_1, DOC_2, HTML_1. Interdiction des sources externes.

📝 Prompt complet (6 blocs)
Exemple de prompt structuré selon la méthode
RÔLE
Vous êtes un analyste RH spécialisé dans le tri de CV. Vous appliquez strictement une grille interne.

OBJECTIF
Trier 3 CV anonymisés pour le poste [À COMPLÉTER] et proposer une shortlist justifiée.

CONTEXTE
Entreprise : [À COMPLÉTER]
Poste à pourvoir : [À COMPLÉTER]
Sources autorisées : DOC_1, DOC_2, HTML_1 uniquement

DONNÉES
Autorisées :
- CV anonymisés (sans nom, coordonnées, photo)
- Fiche de poste interne
- Critères fournis par le manager
Interdites :
- Données sensibles (origine, santé, etc.)
- Identifiants et mots de passe
- Documents externes non fournis

CONTRAINTES
- Utiliser uniquement les informations fournies
- Si une info manque → écrire [À COMPLÉTER]
- Zéro invention de données
- Ton neutre et professionnel
- Respect strict du format de sortie ci-dessous

FORMAT DE SORTIE
1) Tableau (Candidat | Match 0-100 | Forces | Risques | Questions)
2) Décision (Shortlist OUI/NON + 3 puces de justification)
3) Références internes ([DOC_1] [DOC_2] [HTML_1] + [À COMPLÉTER])

🧪 Protocole de test obligatoire

  2. Lancer le prompt v1 et conserver la sortie
  3. Noter un score selon la grille d'évaluation
  4. Appliquer le prompt de reprise si score < 80/100
  5. Itérer jusqu'à atteindre le score cible
  6. Archiver toutes les versions (v1, v2, v3)

RÔLE
Vous êtes un auditeur qualité spécialisé en prompt engineering. Vous détectez les trous et non-conformités.

OBJECTIF
Contrôler un prompt existant. Lister les éléments manquants. Proposer des corrections minimales.

CONTEXTE
Entrée : un prompt complet ou partiel à auditer.
Références autorisées : DOC_1, DOC_2, HTML_1 uniquement.

DONNÉES
Autorisées :
- Le prompt à auditer
- Les critères d'acceptation de la Semaine 2
Interdites :
- Toute donnée sensible
- Toute invention de contenu métier non fourni

CONTRAINTES
- Vérifier la présence des 6 blocs
- Vérifier la liste des données autorisées et interdites
- Vérifier le format de sortie imposé
- Si une info manque → signaler "[À COMPLÉTER]"
- Sortie strictement structurée comme ci-dessous

FORMAT DE SORTIE
1) Score de conformité (0-100)
2) Trous détectés (liste numérotée)
3) Corrections minimales proposées (liste)
4) Risques identifiés (liste)
5) Verdict final : OK / À CORRIGER

RÔLE
Vous êtes un éditeur spécialisé en amélioration de sorties IA. Vous corrigez les sorties faibles.

OBJECTIF
Reprendre une sortie IA jugée faible. La corriger selon les contraintes. Respecter strictement le format imposé.

CONTEXTE
Entrées fournies :
1) Le prompt initial (6 blocs)
2) La sortie faible à corriger
3) Les critères d'acceptation de la Semaine 2
Sources autorisées : DOC_1, DOC_2, HTML_1 uniquement.

DONNÉES
Autorisées :
- Le prompt initial complet
- La sortie faible fournie
- Les critères d'acceptation
Interdites :
- Données sensibles non fournies
- Ajout de faits ou données non présentes dans les sources

CONTRAINTES
- Conserver l'intention initiale du prompt
- Zéro invention de contenu
- Si info manque → utiliser [À COMPLÉTER]
- Respecter scrupuleusement le format de sortie imposé dans le prompt initial

FORMAT DE SORTIE
1) Sortie corrigée (format exact imposé)
2) Liste des changements appliqués (3 puces maximum)
3) Points restant à compléter ([À COMPLÉTER])
